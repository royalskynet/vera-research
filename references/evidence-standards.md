# 證據標準與深度門檻（Evidence Standards）

本檔定義「什麼叫查夠了」。預算（`budget.py`）管上限，本檔管**下限**；兩者一起用：在預算內達到門檻才算一格 `FILLED`，預算用盡未達門檻的格 `CLOSED` 並依 round2-merge 規則改中性事實或刪除。「查過且無一手來源」才算查夠；「沒預算」不是未達門檻的正當理由——定額加碼規則見 `deep-dispatch.md`。

## 來源分級（S1 最強 → S5 最弱）

| 等級 | 定義 | 例 |
|---|---|---|
| S1 | 官方名冊、監管機關、法院、政府登記 | FinCEN MSB 名冊、FINTRAC MSB 名冊、香港公司註冊處 TCSP 名冊、MAS 金融機構名錄、FCA Register、OFAC、法院判決庫、公司登記處 |
| S2 | 主體自身的正式文件 | 官網條款、隱私與 AML 政策頁、API 文件、狀態頁、審計報告、年報、招股文件 |
| S3 | 獨立第三方 | 主流財經／產業媒體原創報導、分析機構報告、學術文獻、行業協會 |
| S4 | 主體自報或關聯方 | 新聞稿（PR Newswire 等）、公司部落格、合作方部落格、LinkedIn 公司頁、創辦人專訪、競爭對手對比頁 |
| S5 | 社群與匿名 | Reddit、Twitter／X、Trustpilot、論壇、評論站 |

各級能證明什麼、不能單獨證明什麼（依主張類型選來源，不是「官方一律優先」）：

| 等級 | 可以證明 | 不能單獨證明 |
|---|---|---|
| S1 | 法律要求、登記或裁判內容、申報事實 | 文件未直接處理的延伸結論 |
| S2 | 主體自述、功能規格、公告內容、費率與條款 | 實際成效、業界領先、客戶滿意、爭議清白 |
| S3 | 獨立報導、分析結果（限方法與樣本範圍內） | 未披露的商業條款、超出樣本的普遍結論 |
| S4 | 「主體稱／新聞稿稱／合作方稱」 | 任何既成事實 |
| S5 | 「有用戶反映」、後續調查線索 | 任何核心結論 |

寫法規則：
- S4 只能支撐「主體自述 X」，正文須帶「據公司自述」「據新聞稿」「據合作方所述」等限定語；不得寫成既成事實。
- S5 只能支撐「有用戶反映 X」，須寫明平台與時間，不得作為唯一來源。
- 同一事實有 S1／S2 時，S4／S5 只作補充，不得取代。
- 兩個來源說法不一 → 兩說並列各掛 `[N]`，正文寫「公開來源對此口徑不一」。

## 主張處理（借鏡 evidence-research-report 證據政策）

- **產品能力**：官方文件可寫「官方文件顯示／公司稱」；要寫「能有效降低風險」需要成效資料或獨立證據。側欄／目錄的產品名只是導航，不構成能力事實——須抓取該能力的實質頁面（overview／integration／limits／compliance）提取規格與上限後，才能以「官方文件顯示」落筆。
- **合作關係**：優先雙方公告；只有單方公告時寫明來源邊界，不擴大成「仍持續合作」。
- **法律／監管**：優先現行法規、主管機關原文與正式解釋；媒體只能補充背景。
- **爭議、訴訟、制裁**：區分指控、立案、裁判、和解與最終結果，保留日期與程序狀態。
- **不存在／未提供**：除非權威完整資料能證明，不寫「不存在」；一律寫「本次已查阅的公开来源未能确认……」（這是可核實的中性事實，可掛所查名冊或來源的 [N]）。
- **法定實體名 ≠ 品牌名（盡調核心）**：查名冊、docket、訴訟、制裁前，先從 S2 條款／官方文件撬出**持牌主體／簽約主體的法律名稱**（`Limited`／`LLC`／`UAB`）。以品牌名查「無」，不構成「無牌」「無負面」結論；要換法定實體名、前身品牌、別名、負責人姓名各查一次。負面記錄「未檢索到」很可能是查的角度／名字錯，不是真沒有。
- **時效性**：可能變動的功能、合作、牌照與政策必須附資料截至日期（`资料截至 YYYY-MM`）。
- **推論**：不寫。報告只收「有來源可掛 `[N]`」的事實，以及由這些事實直接構成的判斷；查不到來源的推測一律刪除，不以 `[推论]` 或任何標記保留。
- **來源衝突**：並列衝突事項、A／B 說法與日期與等級、哪個較能直接證明及理由、仍無法判斷的部分；不自行消除差異。
- 重大、具爭議或直接影響決策的主張取兩個彼此獨立來源；一份直接且權威的 S1 原始文件已完整證明時，不為湊數重複引用。

## 定稿核對＝逐項，不是抽樣

`validate_report.py <報告> --check-list` 列出每條帶 [N] 的主張與來源 URL，逐行確認主體、範圍、時間、限定語相符；`--check-urls` 檢查存活。不使用外部模型當引用裁判，不讀 shell 啟動檔與 API key。

## 硬門檻（未達不得標 FILLED）

| 項目 | 競品調研（competitor） | 服務商盡調（vendor-dd） | 學術（academic） |
|---|---|---|---|
| 每格最少來源數 | 2 個不同網域 | 2 個不同網域 | 2 個不同網域 |
| 每格最少非 S4／S5 來源 | 1 | 1 | 1 |
| 牌照／認證／會員資格類主張 | 該平台官方合規頁＋監管機關名冊各 1 | **每一項**自述牌照都須做 S1 名冊對照 | 不適用 |
| 每個維度分析段 | ≥300 字 | 重點維度 ≥300 字；輔助維度（D1／D5／D8）一段 | ≥300 字 |
| 必答問題（questions-*.md） | 每格登記題（`budget.py ask`）全數結案：有 `[N]` 或寫明「公開來源未見」 | 同左 | 依題自定 ≥3 題，同樣登記 |

`scripts/check_report.sh <報告> --mode <competitor|vendor-dd|academic>` 會機械檢查引用結構與禁詞；每格來源數與 S1 對照由整合 checklist 與第三輪反方（`register-unchecked`／`self-reported-only` 旗標）把關。

## S1 名冊對照的寫法

名冊查得到 → 正文寫「於 <機關> 名冊登錄為 <名稱>，牌照類型 <T>，狀態 <S> [N]」，[N] 指向名冊查詢頁。
名冊查不到 → 這是**可核實的中性事實**，正文寫「於 <機關> 公開名冊（查閱 YYYY-MM-DD）未見以 <名稱> 登錄之記錄 [N]」，[N] 同樣指向名冊頁。不得寫「無法核實」「待核實」。
名冊需要互動查詢且頁面打不開 → 記入缺口清單，第二輪用通道 A 渲染；兩通道皆失敗 → 正文寫「<機關> 名冊為互動查詢頁，本報告未取得其查詢結果」並刪除依賴該對照的推論。

## 風險結論映射（負面事實 → 風險等級，強制）

風險等級**只由查到的負面事實決定**；證據多寡另寫在「證據完整度」欄，兩欄互不推高。「未公開」「只有自述」不是負面事實，不得標「高」；查到的負面事實也不得因「需以正式文件複核」被洗成待辦或降級。

| 證據狀態 | 風險等級 | 證據完整度 | 禁止的寫法 |
|---|---|---|---|
| S1／S3 查到重大負面事實（牌照吊銷或暫停、制裁命中、刑事追訴、客戶資產損失未賠付） | 高 | 依來源 | 不得配「中/低」＋「需以正式文件複核」 |
| S1／S3 查到一般負面事實且未結（罰款、上訴中處分、民事訴訟），牌照未受限制 | 中 | 依來源 | 不得升為「高」，也不得寫成待辦 |
| S1 名冊**查無**（自述持牌但名冊未見），或查到但主體／範圍不符 | 高（自述與名冊不符）；主體不符但有合理關聯 → 中 | S1 | 查無本身就是結論，不寫成待辦 |
| S1／S3 查到負面事實但已整改、已結案或屬輕微 | 低 | 依來源 | — |
| S1 名冊**查到且相符**，且無負面事實 | 低 | S1 | — |
| 僅 S4 自報，或該事項未公開，且無負面事實 | 未评级 | 仅自述／未公开 | 不得標「高（未核實）」；不得把自報數字當既成事實下「低」 |
| 名冊為互動頁且未取得查詢結果 | 未评级 | 未取得 | 不得當作「查無」 |

寫法規則：

- 名冊查無 → 正文寫「於 <機關> 名冊（查閱 YYYY-MM-DD）未見以 <名稱> 登錄之記錄 [N]」，**同時**在該維度的「风险等级」欄標「高」，依據寫「自述與名冊不符」。
- 僅 S4 自報 → 風險等級「未评级」，證據完整度寫「仅见公司自述」。
- 「未檢索到」→ 風險等級「未评级」或刪除主張，不標「高」也不標「低」。
- 第六章綜合風險矩陣分「風險等級」與「證據完整度（S1–S5）」兩欄，各依上表填。

## 深度 ≠ 更多來源

深度來自三件事：
1. **問題先於搜尋**：每格先從 `questions-<mode>.md` 取必答問題，再從三個視角（監管者／受損客戶／競爭者）各補 1–2 個問題，查詢由問題生成，不是由關鍵字生成（借鏡 STORM 的 perspective-guided question asking）。
2. **宣稱 vs 核實分開寫**：每個維度先列主體／平台的宣稱（S2／S4），再列獨立核實結果（S1／S3），最後才是評述。
3. **跨維度交叉**：一個維度的發現要回頭檢查其他維度（例：牌照主體與營運主體不同 → 回到「主體與註冊」與「合作依賴」補寫）；整合階段逐維度做一次。
4. **深度可觀察特徵**：定稿前以 SKILL.md「深度的可觀察特徵」三條自檢（結論回答「所以呢」、群體對比按普遍性分層、模糊前提還原為可核實事實）。方法做對但結果仍淺（羅列不落結論、平均用力、前提未還原）＝未達深度。

## 通用紅旗信號（主題無關，盡調與對標皆適用）

紅旗＝**自述與可核實事實之間的落差**，這是跨主題最強、最可枚舉的風險信號。以下信號本身不是結論，而是「該格必須查、查完要落結論」的觸發點；命中任一條，該格在正文須以 S1–S3 來源核實後給出明確傾向，不得停在「有待觀察」。信號依普遍性分三層，決定用力輕重：

**🔴 高風險（命中即須在正文正面核實並落結論）**
- **規模與足跡不匹配**：自述規模（員工數、客戶數、交易量、發卡量）與可獨立核實的數字足跡（登記處申報、第三方統計、媒體提及）嚴重不符。
- **無第三方獨立提及**：除自建網站與新聞稿外，無任何獨立來源（媒體、監管、第三方資料庫）提及該主體或其宣稱的業務。
- **自述資質查無**：自述牌照／認證／會員資格在對應 S1 名冊（registry-directories.md）查無登錄，或持照主體 ≠ 營運主體。
- **制裁／處分命中**：法人、品牌、創辦人或高管出現在制裁名單或監管處分記錄。
- **來源矛盾**：多來源對同一事實（成立時間、註冊地、股東、合作方）說法不一，且無法以 S1 消解。
- **合作方自身有風險**：關鍵合作方（銀行、卡組織、託管方、合規供應商）自身有處分、事故或監管警示。

**🟡 需補充核實（命中即須在正文標明核實結果，不得略過）**
- **主體存續時間短**：成立時間短（如 <2 年）卻宣稱長期營運或大規模業務。
- **關鍵資訊不可獨立核實**：創辦人／高管經歷、融資輪次與投資方、營收與獲利，僅見自報（S4）或 LinkedIn（S4），無 S1–S3 互證。
- **聯絡與營運細節存疑**：官方聯絡用免費信箱、註冊地址為代收／虛擬地址、無實體營運痕跡。
- **負面訊號集中**：用戶投訴模式一致（凍結資金、拒付、客服失聯）、裁員、關閉市場、拖欠款項，或高管近期集中離職／拋售。
- **單一依賴**：營運高度依賴單一合作方或單一創辦人，中斷即癱瘓。

**⚪ 反例（缺席未必是紅旗，但須說明「缺席是否可成立」）**
- 未公開審計財報、未列卡組織服務商名單、無漏洞賞金計畫等——對某些規模或業務模式屬正常，正文須判斷「該缺席在此情境是否合理」，而非一律視為風險。

紅旗信號是**觸發器**，不是**結論**：命中後仍走「宣稱 → S1–S3 核實 → 落結論」的既有流程，不得以紅旗標記取代核實。紅旗清單與 D1–D9 的對應：規模足跡→D1/D5、資質查無→D2、制裁處分→D6、來源矛盾→D1/D5、合作方風險→D9、主體存續→D1、關鍵資訊不可核實→D5/D8、聯絡細節→D1、負面訊號→D5/D6、單一依賴→D9。

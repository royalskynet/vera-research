# 第二輪雙通道分派表 與 整合融合規則

本檔由 SKILL.md 的「第二輪」「整合定稿」段獨立而成，供第二輪執行與整合時參照。

## 補強口徑

第一輪缺口工作清單（暫存，非報告章節）逐項記錄：對應平台／維度、具體待證的主張內容、原始嘗試過的 URL、失敗原因分類。每個缺口項兩通道都跑、各恰一次，不重試、不互補跑第二次。總嘗試數 = 缺口數 × 2，寫死不擴大。

**S1 名冊「查無」不是缺口**：名冊查無是第一輪的核實結論，直接寫入報告（「於 X 名冊未見登錄」），不列入缺口清單、不重跑。只有「名冊頁面打不開」才算缺口（進通道 A 渲染）。

## 兩通道分派表

每個缺口項一列，兩欄都要填「跑過／結果」。缺口分類只決定通道 A 的用法。

| 缺口項 | 通道 A：背景反偵測渲染（camofox REST `:9377`） | 通道 B：agent-reach 換角度 |
|---|---|---|
| ❶ 官方頁存在但打不開／SPA | `${CLAUDE_SKILL_DIR}/scripts/camofox_fetch.py @urls.txt`，同批 URL 一次批次；STATUS 非 200 或 BODY 空 → 放棄 | 換語言／角度／替代原始來源（監管公告、名冊、新聞、Wayback、社群）：直接用 `scripts/reach.py` 與 agent-reach CLI，或同批缺口合併一次派遣 `Agent(general-purpose)` 子代理（先 Read agent-reach SKILL.md）；回「事實＋URL＋摘錄」或「查無可信來源」 |
| ❷ 根本找不到來源 | `camofox_fetch.py --search "<關鍵字>"` 一次，取前 3–5 個命中頁再 `@urls.txt` 批次渲染一次 | 同上（同一次派遣內一併處理） |

> 第一輪已用過 agent-reach（Exa／Jina），第二輪通道 A／B 的定位是「換角度／換語言／替代原始來源」，不是重複第一輪的查詢。牌照／監管資質類缺口，第二輪優先下沉 `registry-directories.md` 的名冊。缺口清單上限依模式（competitor ≤10、vendor-dd ≤6、academic ≤8），以 `budget.py phase round2 --gaps` 定案；每缺口格通道 A 恰 1 次抓取＋1 次搜尋（ledger 強制）。規則全文見 SKILL.md「調研預算與停損」。

## Camoufox 觸發判斷樹（通道 A 決策）

**僅在以下全部條件成立時啟用 Camoufox**：

```
需要渲染 = (目標頁面需要 JS 渲染內容 OR 存在登入牆/需認證 OR 為 SPA 路由 OR 存在反爬驗證碼/Challenge)
        AND (Jina Reader 讀取為空 OR 內容明顯不完整/缺失關鍵數據)
        AND (已嘗試 Exa 搜尋替代來源但無果)
```

**判斷步驟**：
1. `reach.py read <URL>` → 若回傳 `200` 且 BODY 含關鍵信息 → **不需要 Camoufox**，直接用 Jina 結果
2. 若 Jina 回傳 `EMPTY` / `403` / `429` / 內容明顯被 JS 渲染阻擋 → 嘗試 `reach.py search` 找替代來源（Wayback、媒體轉載、監管公告）
3. 替代來源仍無果 → 確認目標頁面屬於：SPA/需登入/反爬/動態加載 → **啟用 Camoufox**
4. `camofox_fetch.py --url <URL> --cell <cell>` 或 `--search "<關鍵字>" --cell <cell>`

**典型觸發場景**：
- 交易所 APP 內嵌 H5 頁面（需登入 Cookie）
- 動態加載的交易深度/訂單簿數據
- Cloudflare Turnstile / reCAPTCHA 保護的頁面
- React/Vue SPA 路由（Jina 只抓到空殼 HTML）

**典型不觸發場景**（本次 BingX 實戰全屬此類）：
- 官方幫助中心（Zendesk 靜態 HTML）
- 官方公告/部落格（靜態文章頁）
- 合規/儲備金證明頁（靜態數據表）
- 費率/條款/隱私政策頁

---

務必注意：總嘗試數寫死缺口數×2，不因一條缺口同時在兩通道落空而再補跑。兩通道同時命中且說法不一 → 兩說並列各附來源。

## 整合融合規則

第一輪初稿＋第二輪雙通道結果合併成單一報告：

```
第一輪初稿 ＋ 第二輪補強結果
  ↓
每個缺口項套優先序：
  1) 任一通道補強成功 → 改寫原處敘述並掛 [N]，融入原本所在段落；
     新證據同源亦充實相鄰段落、對比表、摘要與建議（擴大調研＝整體更豐富）
  2) 兩通道皆失敗、但缺口本身是可核實的公開事實（如官方帮助页确实未列出該項）→ 改中性學術表述留在原本自然位置並掛 [N]，去掉所有工作階段標記（嚴禁另立資料缺口清單章節）
  3) 兩通道皆失敗、且不構成可核實的公開事實 → 直接刪除該主張；定稿正文不得殘留 [待核實]、⚠️ 資料缺口、「待確認」「待要求」「暫無查到」等任何表述
     絕不設「補充調查」「資料缺口清單」「未驗證項目彙總」獨立章節或附錄
  ↓
鐵律 4：統計引用數 → 逐項語意核對（--check-list）→ URL 存活（--check-urls）
```

## 嚴禁事項

- **禁用「補充調查」「資料缺口清單」「補充調查結果」等新章節** — 補強是改寫既有內容，不新增過程章節。
- 非公開數字（正樣本率、複核工時、自評基線）不進調研正文。
- 第二輪動作本身不得寫入報告文本（禁詞見 `forbidden-words.md`）。

## 充實規則（擴大調研 ≠ 只填洞）

第二輪帶回的來源通常不只回答原缺口，整合時逐一問：

1. 這個來源還能支撐對比表哪些儲存格？→ 補進去並掛 `[N]`。
2. 同平台段落有無因此可以多寫一個特色做法或監管動態？→ 改寫該段落。
3. 摘要與「建議與啟示」的核心發現是否因新證據改變或可更具體？→ 重寫對應句子。
4. 差距分析的 ✅／⚠️ 是否需要重評？資料不足的儲存格是否已改為中性事實？→ 更新。

充實的內容一律寫進既有章節；章節數、章節順序與第一輪相同。
